# 🚀 Important GitHub Features

## Repository

Stores the complete project, including files, folders, commits, branches, and history.

---

## Branch

Creates an independent workspace to develop new features or fix bugs without affecting the main branch.

---

## Clone

Downloads a complete copy of a GitHub repository to the local computer.

```bash
git clone <repository-url>
```

---

## Fork

Creates your own copy of another person's GitHub repository, allowing you to experiment without modifying the original project.

---

## Pull Request (PR)

Requests that changes from one branch be reviewed before merging into another branch.

Typical workflow:

```
Feature Branch
      ↓
Push to GitHub
      ↓
Pull Request
      ↓
Code Review
      ↓
Approval
      ↓
Merge
```

---

## Merge

Combines changes from one branch into another.

---

## Issues

Tracks:

- Bugs
- Feature Requests
- Improvements
- Tasks

---

## Projects

Organizes development tasks using boards and project management tools.

---

## Wiki

Provides project documentation and user guides.

---

## Releases

Publishes stable versions of software.

Example:

```
v1.0
v1.1
v2.0
```

---

## Tags

Marks important commits for version tracking.

---

## GitHub Actions

Automates workflows such as:

- Testing
- Building
- Deployment
- Continuous Integration (CI)

# 📖 Key Concepts Learned

### Repository

The main container that stores the complete software project.

### Branch

An isolated development environment used to safely build new features.

### Fork

A personal copy of someone else's repository.

### Pull Request

A request for reviewing and merging code into another branch.

### Merge

Combines approved code changes into the target branch.

### Issues

Tracks bugs, feature requests, and project tasks.

### Releases

Provides official software versions for users.

---

# ⚠️ Best Practices

- Create feature branches for new work.
- Never develop directly on the main branch.
- Write meaningful commit messages.
- Review code before merging.
- Keep Pull Requests focused and small.
- Document projects using README files.
- Create Releases for stable software versions.

---

# ❌ Common Mistakes

- Working directly on the main branch.
- Creating very large Pull Requests.
- Ignoring code reviews.
- Poor commit messages.
- Not documenting the project.
- Forgetting to synchronize with the latest repository changes.
